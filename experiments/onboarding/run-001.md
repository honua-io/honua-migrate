3. [migrate #154](https://github.com/honua-io/honua-migrate/issues/154): normalize numeric/named statuses, preserve review/timeout outcomes and stop promptly. Command exit zero cannot be the harness success oracle.
4. [server #4811](https://github.com/honua-io/honua-server/issues/4811): reconciliation compares UTM source bounds to longitude/latitude target bounds and rejects explicitly requested reprojection. Do not suppress fidelity checks to make the run green.
5. Agent/harness corrections: use the documented `connect` protocol (`auto`), MapLibre namespace import, returned geometry rather than misleading latitude/longitude attributes, and explicit queried field bindings after imported field-name normalization. These errors are not proven SDK primitive gaps.
6. Unclassified rendering boundary: `mountSource` produced valid point GeoJSON and reported 26 features, but renderer observations remained empty. The experiment's Vite worker URL imports returned a function and caused `endsWith` errors; those attempted overrides were removed. Next run should start from the supported scaffold and isolate worker/runtime setup before declaring an SDK renderer defect.
7. Recorder improvement: timeout now terminates the owned process tree, and receipts explicitly label exit status as command-only. Four focused checks passed, including nested-process timeout in approximately 1.3 seconds with a one-second budget.

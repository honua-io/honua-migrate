# Run-004: dimensional imports and the Editor backend

This exploratory run fixes source-ordinate capture, feature-type publication and
dimensional metadata, while exposing date-only and nonspatial-table gaps. It does
not complete or qualify the four-app conversion. [Machine-readable observations](run-004.json)
retain every recorded job and the available command timings, including failures.

## Environment and method

A fresh local database and separate Redis instance isolate this run from the
user's Powerplants demo. Service movement uses the Honua server importer through
`honua-migrate services arcgis plan/apply/resume`; Python only orchestrates and
independently compares source/target responses. Source Esri services remain read-only.
The CLI terminal-status fix is commit f822262 (PR #157).

The managed host comes from server 93d75f2eb, with four explicitly rebuilt
assemblies from 04f7e4c78; the final flight retry updates Core/Postgres with the
dimensional-publication changes committed as eb754214b. Private manifests retain
DLL hashes, the source patch and exact runtime provenance. This is component-overlay
evidence, not a fresh full-host build. The initial host start failed because the
new database lacked PostGIS; provisioning the extension fixed that preflight.

## Reusable improvements and evidence

- Server [PR #4830](https://github.com/honua-io/honua-server/pull/4830) preserves
  all 8/2/2 Editor feature types, their normalized type fields and valid prototype
  field bindings. Full template presentation and unsupported diagnostics remain open.
- Final flight readback advertises `hasZ=true`. A fresh independent comparison
  matches all 1,963 natural keys, every non-OID attribute and path/vertex topology.
  Across 3,926 vertices, maximum XY delta is below 4.50e-10 degrees and Z delta
  below 7.30e-12. Source captures are mutable, not a frozen benchmark dataset.
- Six real PostGIS tests pass for both subtype encodings and 2D/Z/M/ZM points.
  The first run caught a POINTM publishing failure; topology normalization fixes it.
  Changed-project builds and scoped formatting pass. Broad pre-pr/architecture
  gates were not run locally.
- Editor's first browser start failed by attaching Terra Draw to a read-only source.
  The app now checks `applyEdits` before binding drawing. Installed-SDK browser
  checks cover all three row counts, layer switching, selection without geometry,
  area reload, a 20-of-49 Open search, and rendered OpenFreeMap attribution.
  The subsequent production build passes in 5.376 seconds; these browser checks
  used the development server. CRUD and attachment writes remain unverified.

## Reuse and metrics limits

A private PostgreSQL custom dump, runtime/configuration manifests and raw captures
are cached outside source control. The retained Redis AOF volume is separate.
Restore, attachment-asset completeness and immutable-source qualification have
not run; this is an exploratory checkpoint, not an admitted snapshot baseline.

The metrics distinguish command exit status from import fidelity. Nonzero resume
exits for NeedsReview/Failed are correct CLI behavior. Available stage timings
exclude unmetered agent work and build-queue wait. Model cost/tokens are unavailable,
not zero. Fresh agent conversion repeats, complete browser behavior and full
backend fidelity still need their own evidence.
